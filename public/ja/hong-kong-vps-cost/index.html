    よくある質問

    おすすめの構成はどう決めていますか？

    CPU とメモリの条件を満たすすべてのサーバープランを、各オブジェクトストレージ・CDN と組み合わせ、1 か月の費用を一つずつ計算しています。中身はプラン料金、含まれる分を超えた転送量（大手クラウドでは 1 GB ごとのデータ転送料金）、ストレージ、リクエスト、CDN の転送量です。画面には最大 3 つを出します：利用者に近いリージョンで最も安いもの、契約先が最も少なく請求がまとまるもの、そして別の地域ではっきり安い場合はそれ。残りは比較表にあります。CDN を使う場合は、リクエストの 80% を CDN のキャッシュが返し、残り 20% はオリジン（元のサーバーやストレージ）へ取りに行く前提で、その分はオリジン側の料金体系で計算します。

    大手クラウドはなぜこんなに高いのですか？

    主な原因は転送料金です。AWS、Google Cloud、Azure はインターネットへ送る 1 GB ごとに約 $0.08〜$0.12 を請求します。一方、多くの VPS は月 1〜20 TB の転送量がプランに含まれています。月に数 TB 送ると、大手クラウドでは転送料金がサーバー代より高くなることもよくあります。

    「静的ファイル」とは？どれくらい入れればいいですか？

    誰に送っても中身が同じファイルのことです。画像、ダウンロード、動画、スクリプトなど。サーバーの代わりにオブジェクトストレージや CDN から配信できます。目安は、ブログならほぼ静的（80% ほど）、API やプロキシは 0%、ダウンロードサイトはほぼすべて（95%）です。

    オブジェクトストレージと CDN を組み合わせる価値があるのはどんなとき？

    転送量の大半が静的ファイルで、サーバーのプランに含まれる転送量を超えるときです。Cloudflare R2 は転送料金が無料で、Backblaze B2 も Cloudflare や Bunny 経由なら無料です。月に数 TB のダウンロードでも、数百ドルではなく数ドルで済むことがあります。

    アップロードは無料なのに、ダウンロードはなぜ有料？

    事業者は、自社ネットワークから出ていく通信の分だけ上流の回線にお金を払っています。入ってくる通信は顧客を呼び込むものなので無料にしています。そのため、サーバーへのアップロードは無料で、サーバーから利用者へ送る分（データ転送）に料金がかかります。

    Google Cloud の Premium ティアと Standard ティアの違いは？

    Premium は Google 自身のネットワークで利用者に最も近い地点まで運んでからインターネットに出し、送り先ごとに料金が決まります。Standard はデータセンターの近くでインターネットに渡すため安くなります。Azure の「Microsoft ネットワーク」と「インターネット」のルーティングも同じ考え方です。

    中国本土への転送はなぜ高いのですか？

    中国へ入る国際回線は少なく、高価だからです。Google Cloud の Premium ティアでは中国向けが別料金で、通常の約 2 倍です。しかも料金に関係なく、中国向けの経路は遅いことがよくあります。通常はアジア太平洋のリージョンが最も近いので、このページの遅延測定で比べてみてください。

    性能は比較しないのですか？

    このツールは価格とスペックで絞り込むもので、ベンチマークではありません。共有 CPU のプラン（表に表示）は、同じ物理サーバーのほかの利用者が忙しいと遅くなることがあります。気になる場合は詳細設定で外せます。

    小さいサーバーを何台か借りて転送量を稼ぐのは得？

    小さいプランを何台か合わせると、大きいプラン 1 台より転送量が多くなることがあります。この組み合わせは自動では探さないので、詳細設定でサーバー台数を変えて比べてください。

    価格は正確ですか？いつ更新されますか？

    すべての価格を各社の公式料金ページと手作業で照らし合わせています。確認日はページ下部にあり、表の各行から出典へ飛べます。価格はすべて付加価値税などの税抜きで、お住まいの地域によっては請求時に税が加わります。各社は米ドルかユーロで料金を出しており、ほかの通貨で表示するときは欧州中央銀行の固定の参考レート（日付はページ下部）で換算するため、実際の請求額とは少しずれることがあります。誤りを見つけたら GitHub の issue で教えてください。

    遅延はどう測っていますか？中国本土への経路は？

    ブラウザから、このページにある各データセンターへ小さなリクエストを何回か送り、時間を測っています。測定先と方法は Me2Cloud と同じで、1 回目は準備として捨て、続く 3 回の中央値を使います。実験室の数字ではなく、あなたの回線での実際の遅延です。中国本土への経路の良し悪しは事業者や通信会社によって大きく違い、価格からはわかりません。利用者が中国にいるなら、中国からこのページを開いて（または利用者に開いてもらって）、香港と東京の数値を比べてください。
